# PWA Design System Admin Panel — Specification (v1)

Product: a PWA admin panel that is both (a) the living documentation / editor of a design system
(tokens + components) and (b) a reference admin app built only from that design system.

Owner standards applied: KB skills `ui:admin-panel-design-standard` v2.0.5, addendum v2.1,
`pwa:product-standard` v1.0, `ui:ssot-component-library`. All code, comments, docs: English.

## Hard rules
- Vanilla HTML + CSS + ES Modules. NO framework, NO bundler, NO npm runtime dependency.
  Node (>=20) is used only for scripts and `node --test`. Icons: inline SVG Lucide-style set in ONE file `js/icons.js` (SSOT).
- Single source of truth: design tokens live in `tokens/tokens.json`. `css/tokens.css` is GENERATED by
  `node scripts/build-tokens.mjs`. Never edit the generated file by hand.
- No raw colour literals (`#hex`, `rgb(`, `hsl(`) in any CSS/JS outside `tokens/tokens.json` and the generated `css/tokens.css`.
- No native `<details>/<summary>`, no native `<select>` carets: menus/selects are custom popovers.
- Whole list/table rows clickable (no per-row "Open" button). Touch targets >= 44px on phones.
- No fake behaviour: every visible control works, or is not rendered. Mock data must be labelled "mock".
- Do not commit, push, deploy, or touch files outside the repo. Do not add dependencies.

## Layout (addendum v2.1)
- Top bar 64px, sticky, opaque: logo + name left; language (EN/中文 toggle that really switches UI strings),
  theme menu (Light / Dark / System), account menu right. No status chips.
- Sidebar: icon rail 64px (modules: Overview, Tokens, Components, Settings + "More" popover) + context panel ~260px
  (content depends on the active module). The toggle collapses ONLY the context panel. Rail icons have instant tooltips
  (hover + focus). State persisted in localStorage (preference only).
- Phones (<768px): bottom tab bar + "More" sheet (owner-approved decision), no sidebar.
- Tablet 768–1024 is its own breakpoint: rail + panel collapsed by default.
- Default theme: LIGHT on first visit. Dark = neutral blue-black. One accent colour (emerald); semantic hues only as dots/pills.
- Density tokens Comfortable / Compact (Settings > Appearance), applied via `data-density` on `<html>`.
- iOS: `viewport-fit=cover`, safe-area insets used, opaque theme-aware top surface, inputs 16px on phones,
  manifest `theme_color` matches top bar.

## Pages (hash router `#/overview`, `#/tokens`, `#/components`, `#/components/<name>`, `#/settings/<section>`)
1. **Overview**: counts (tokens, components), recent token edits (from localStorage change log), install / update / offline status card (real data).
2. **Tokens**: groups Color / Typography / Spacing / Radius / Shadow. Each token row: name, value, live swatch/preview. Click row to edit
   (colour input, text input) → live preview on the whole app via CSS variable override; overrides persisted in localStorage, "Reset"
   per token and "Reset all". Export buttons: download `tokens.json`, copy generated CSS. Light and Dark values editable separately.
   Change log (token, old, new, time) kept (last 50).
3. **Components**: list in context panel; detail page = live preview + playground controls (props) + states row
   (default, hover, focus, disabled, error, loading where applicable) + copyable HTML snippet.
   Required components (each lives in `components/<name>.js` + `css/components/<name>.css`, registered in `components/registry.js`):
   button, input, select (custom popover), checkbox/switch, tag/pill, tabs, table (search, clear, sort, filter, pagination, row click,
   loading/empty/error states, mock rows), modal (focus trap, Escape, focus return), toast, tooltip, popover menu.
4. **Settings**: General (landing page, density, default page size), Appearance (theme, density, panel preference, reduced motion),
   About/Version (real version + build id from `version.json`), PWA & Updates (installed version, Check for updates, Update now, offline state, clear cache with confirm).

## PWA (pwa:product-standard)
- `manifest.webmanifest` with name, short_name, start_url `./`, scope `./`, display standalone, theme/background colours, icons 192/512 + maskable
  (generate simple PNG icons with a Node script `scripts/build-icons.mjs` WITHOUT dependencies — write minimal PNG encoder using `zlib`).
- `sw.js`: versioned cache name from build id; precache app shell; network-first for navigations/HTML, cache-first for versioned static assets;
  delete obsolete caches on activate; NEVER `skipWaiting()` automatically — only on message `{type:'SKIP_WAITING'}`.
- Update UX: detect waiting worker → visible "New version available" + "Update now"; click disables button, shows loader overlay,
  posts SKIP_WAITING, waits for `controllerchange`, reloads ONCE. Failure state with retry. Offline banner/state. No reload while any form/token edit is dirty without a Save/Discard/Cancel prompt.
- Version truth: `version.json` (`{"version":"0.1.0"}`) is the only manual source; `node scripts/stamp-build.mjs` writes `js/build-info.js`
  (version + build id = git short SHA or timestamp) and injects the build id into `sw.js` (constant line `const BUILD = '...'`). UI and SW read the same value.
- Offline contract (document in Settings > PWA & Updates and README): shell, tokens, components docs work offline; no server writes exist.

## Tooling
- `node scripts/serve.mjs [port]` — tiny static server (no deps) with correct MIME types and `Cache-Control: no-cache` for `sw.js`/HTML.
- `node scripts/check.mjs` — ratchet: fails on raw colour literals outside tokens, native details/summary, missing generated-file sync,
  component registry entries without css/js files, `<select>` usage in components. Exit code non-zero on failure.
- `npm test` = `node --test tests/` — unit tests: token build determinism and light/dark parity, check.mjs fixtures (pass + fail case),
  manifest/sw validity (required fields, no auto skipWaiting), registry integrity, router route table, i18n key parity EN/中文.
- `package.json` scripts: `build`, `serve`, `check`, `test`, `verify` (= build + check + test). No dependencies section entries.

## Interpretation policy (unstated cases)
- Accept liberally for user-facing input (trim whitespace, accept `#abc` and `#aabbcc` colours, case-insensitive hex); reject strictly
  invalid token values with an inline error and DO NOT apply them (exact rule: invalid never reaches CSS variables).
- Exact rules: no raw colours outside tokens; SW never auto-skipWaiting; Light is the default theme; version shown in UI equals `build-info.js`.
- If the spec is silent: choose the simplest option consistent with the existing code and the owner standards, and record the choice in `docs/DECISIONS.md` (one line each). Do not ask.
- Worked lenient example: user types ` #0F0 ` into a colour token → stored as `#00ff00`. Worked strict example: `#12` or `red` → inline error "Enter a hex colour like #1a2b3c", variable unchanged.
