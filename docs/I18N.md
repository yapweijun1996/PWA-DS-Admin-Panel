# Internationalisation (English / Chinese)

Languages: English (source) and Simplified Chinese (`zh`). The language toggle in the top bar switches the whole UI, including components, the Guide and the ERP/CRM/School examples.

## How it works
- **Shell strings** use flat keys in `translations.en/zh` (`js/i18n.js`) through `t('overview')`.
- **Everything else is keyed by its English source text.** `t('Choose a date')` or `t('{count} items', { count })` look up `js/i18n/zh/*.js`; English is the fallback, so English output never changes.
- **Runtime localizer** (`js/localize.js`) translates rendered text and `aria-label`, `placeholder`, `title`, `alt` after each render and for text changed later (dialogs, toasts, announcements). It uses `js/i18n/match.js`: exact match first, then `{name}` templates; captured values are localized recursively. The reserved placeholder names `{day} {year} {time} {month} {weekday}` match only dates, so a date template cannot swallow ordinary sentences. Templates need at least two literal letters.
- Component usage-guide metadata (`guide.purpose`, `props`, ...) is translated by the same dictionary.
- Mark text that must stay as written with `translate="no"` (code, IDs, brand). Intentionally untranslated rendered strings (proper nouns, mock record names, palette names) are listed in each dictionary file's `keepEnglish`.

## Adding or changing UI text
1. Write the English text in the source as usual.
2. Add `'English text': '中文'` to the closest `js/i18n/zh/<area>.js` (or a new file registered in `js/i18n/zh/index.js`). A key may exist in only one file; placeholders in the value must come from the key.
3. Run the coverage checks below. Releases must report zero leftover English.

## Coverage checks (development tools, not shipped in the bundle)
Run from the browser console of a local server (`node scripts/serve.mjs 8080`) after setting the language to Chinese:
```js
const { scanI18n } = await import('/scripts/i18n-scan.mjs');
await scanI18n();                       // every route, default render
const { sweepI18n } = await import('/scripts/i18n-sweep.mjs');
await sweepI18n({ paths: ['/components/modal'] }); // opens menus, dialogs and drawers by clicking buttons
```
Both return leftover English text (text nodes and accessible attributes). `tests/i18n.test.mjs` guards dictionary integrity (no duplicate keys, Chinese present, placeholders valid, every literal `t('...')` key translated, matcher behaviour).

## Not covered
Dates, numbers and currency formatted by a component's own `locale` prop follow that prop (for example the date-picker demo's English (UK) locale selector). Mock data names stay English by design (declared in each dictionary's `keepEnglish`). The playground prop editors (for example the "Field label" input of the date picker) keep their English source values because they are editable code-level props; the preview and the accessible names built from them are translated.

## Lessons that shaped the tools
- A scan that only opens pages misses dialogs, menus and states reached by clicking; use the sweeps.
- Sweeps leave forms dirty and the unsaved-changes guard then blocks every later route change, silently re-scanning one page; `goto()` in `scripts/i18n-scan.mjs` disables the guard.
- Never apply reviewer suggestions as global substring replacements: one short suggestion once turned many unrelated words into "课程". `tests/i18n.test.mjs` now guards that term.
- Composed sentences belong in templates with unique placeholder names (a repeated name makes the last capture win).
