## A. PWA robustness (found by the manager on the live site; highest priority)
1. **Mixed-version precache.** GitHub Pages' CDN can serve some files of a new deploy and stale copies of others for ~10 minutes. The service worker then installs a NEW build id with OLD files (observed: live `sw.js` newer, `js/router.js` and `js/build-info.js` older, so the app stayed at 0.4.0 and showed "Page not found" for new routes). Fix: (a) precache requests use a cache-busting `?v=<BUILD>` query (and `cache: 'reload'`), and lookups ignore the query; (b) during `install`, after fetching, verify that the fetched `js/build-info.js` BUILD equals the worker's own BUILD (and optionally a content hash manifest `precache-manifest.json` generated by `scripts/stamp-build.mjs`); on mismatch FAIL the install so the old worker keeps serving and the browser retries later; (c) unit tests with a fake CacheStorage/fetch for match, mismatch and retry.
2. **Unknown route after deploy.** A returning user with an old cached version opens a deep link to a route the old build does not know and sees a bare "Page not found". Make the not-found view check for a newer version (call `registration.update()`; if a waiting/installing worker exists show "A newer version is available - Update now" using the existing update UX, with the same loader and single reload); if no update exists show the normal not-found view with search and a link home. Also call `registration.update()` on app start and when the tab becomes visible (throttled to once per 10 minutes).
3. Document the CDN behaviour and these protections in `docs/DEPLOYMENT.md`.

## B. Kit export (what lets a NEW project pick a look)
`node scripts/export-kit.mjs --kit <enterprise|liquid|ops> [--palette blue] [--out dist-kit]` generates a versioned, dependency-free static bundle: `tokens.css` + `appearance.css` limited to the chosen kit/palette (both themes), the component CSS and JS modules, icons SSOT, the boot script snippet, a `kit-manifest.json` (version, build, kit, palette, file hashes) and a `README.md` with a 10-line quick start (link the CSS, add `<html data-kit data-theme data-palette>`, import components). Add `npm run export:kits` that exports all three into `dist-kits/` (git-ignored). Add a tiny consumer demo page inside each exported bundle (`demo.html`) that renders a button, input, combobox, table and chart using only the bundle. Tests: the export is deterministic, contains no files outside the bundle, the manifest hashes match, and `demo.html` references only relative files that exist. Document in `docs/USAGE.md` (how a new project adopts the design system, chooses a kit, theme and palette, adds a component, and upgrades with the CHANGELOG).
